- 2026-10-28: LaTeX details (Claude's call, recorded in `src/core/equation/CLAUDE.md` Gotchas): commands match longest-prefix because spaces are stripped, so `\sin x` is `\sin`·x (and needs parentheses) and `\pix` is π·x. Any function takes `()` or `{}`, plain names too (`sin{x}`). `\left(`/`\right)` are plain `(`/`)`, so mismatched pairs like `\left(x)` are accepted. `\frac{a}{b}` is one atom, so `\frac{x}{2}^2` = (x/2)². `\sqrt[n]` isn't supported.
- 2026-10-28: `toLatex` writes `\min`, `\max` and `\lfloor … \rfloor`, so the tokenizer now accepts those three as well, beyond the original LaTeX table (Claude's call; without them, previews of min/max/floor couldn't be parsed back). Rendering rules are in `src/core/equation/CLAUDE.md` § Pretty Display.
- 2026-10-28: Parser details (Claude's call, recorded in `src/core/equation/CLAUDE.md` Gotchas): spaces are stripped before tokenizing, so `s in(x)` = `sin(x)`. `2|x|` and `|x||x|` work as implicit multiplication. `1e3` means 1·e·3. `3.` and `1.2.3` are errors. `|a|` is stored as `abs(a)` in the tree.

- 2026-10-28: Safety limits (Claude's call, recorded in `src/core/equation/CLAUDE.md` Gotchas): the 200-character limit counts the raw input, spaces included, so a huge paste fails before any work; the error points at position 200. Depth 50 counts `()`, `{}`, bars, `\lfloor` and function calls (unary minus and `^` chains don't count). The 500-node limit can't be reached within 200 characters (densest is `xx…x` = 399 nodes), so it's tested through the internal `parseWithLimits()`.
- 2026-10-28: Evaluator rules (Claude's call, recorded in `src/core/equation/CLAUDE.md` Gotchas): any step that isn't a finite number becomes `NaN`, so `1/0`, `ln(0)` and overflow like `exp(1000)` are gaps in the track, never infinities, and `0*(1/x)` at 0 stays `NaN`. `x^(1/3)` is `NaN` for negative x (no real cube roots), and `0^0` = 1, as in JavaScript. These change which tricks work for golfing, so the user can adjust them.
- 2026-10-28: The `toLatex` read-back promise holds only while the preview fits in 200 characters (Claude's call, recorded in `src/core/equation/CLAUDE.md` § Pretty Display). The fuzz test found that `\left|`, `\frac{}` and `\cdot` can push a long equation's preview past the length limit. The game never parses a preview, so the limit stays, and the fuzz test requires exactly the length error in that case.
- 2026-10-28: Track samples (Claude's call): `sampleTrack(f, from, to, step = SAMPLE_STEP)` in `src/core/sim/track.ts` takes plain numbers, not a `Level` (that type arrives in Section 4), and returns typed arrays (`x`, `y`, `slope`, `curvature`) so the step loop won't allocate. Each x is `from + i·step`, and the last sample is exactly `to` even when the range isn't a whole number of steps. NaN is kept in the arrays; the broken-track check comes with the fail-conditions task. `constants.ts` gains each tuning number when a task first uses it (so far `SAMPLE_STEP`, `DERIVATIVE_STEP`).
- 2026-10-28: Cart physics (Claude's call): `startCart(track, speed)` and `stepCart(track, cart, drag = DRAG)` in `src/core/sim/physics.ts` update one `Cart` object in place (`t`, `x`, `y`, `v`, `angle`, `normal`, `segment`), so the step loop allocates nothing. Slope, curvature and height are linearly interpolated between track samples, not re-evaluated from f. Semi-implicit Euler with `DT = 1/240`, `G = 9.81`, linear `DRAG = 0.02`. When speed drops to 0 or below the cart stays put (never rolls back), and x is clamped at the last sample; deciding `STALLED` or a win is left to `simulate`. `normal` is g·cos θ + v²κ at the new position, ready for the `FLEW_OFF` check.

- 2026-10-28: Simulate input (Claude's call): `simulate(level: SimLevel, f)` in `src/core/sim/simulate.ts` takes `SimLevel` (`bounds`, `start`, `end`, `obstacles`), the subset of Section 4's `Level` the sim reads, so a full `Level` passes straight in. `Obstacle` is defined in `src/core/sim/collide.ts` for now; Section 4's `level/types.ts` should re-export it rather than define a second one (two `export *` of the same name in `src/core/index.ts` would clash). `FailReason`/`SimResult` match the shared contract exactly.
- 2026-10-28: Fail-check details (Claude's call): checks run in the harness order. BROKEN_TRACK also covers a non-finite slope or curvature, so a curve whose domain starts exactly at a station (`sqrt(x)` with start.x = 0) is broken, because the slope probe at x−h is NaN. A jump is reported at the last sample before the gap; a NaN point's `failAt.y` is the last finite height (or start.y). HIT_OBSTACLE tests the cart circle (centre CART_RADIUS along the track's upward normal) at every sample, which also covers the track touching. In the ride, the order per step is FLEW_OFF, then the win (x ≥ end.x), then STALLED (v ≤ 0); TIMEOUT is counted in whole steps (30 s = 7200 steps).
- 2026-10-28: Path recording (Claude's call): `path` gets the start point at t = 0, then a point every `PATH_EVERY = 4` steps (60 fps), plus the final step if the run ended between frames, so the last point is exactly `failAt` (or the win point, with `t = duration`). Fail-fast results (checks 1–5) have an empty path, since there's no ride to replay. The point type is exported as `PathPoint` (same shape as the shared contract).
- 2026-10-28: FLEW_OFF at t = 0 (Claude's call, from the Section 3 review): `simulate` checks the normal force only after each step, so a hilltop right at the start station flies off one step (1/240 s) in, and FLEW_OFF's `failAt.t` is never 0. Kept as is: the player sees the same thing.
- 2026-10-28: The 50 ms benchmark times a warm run, best of 3, so it catches real slowdowns but not a slow first (cold) run. That's deliberate, after Section 2's GC-pause flake.
- 2026-10-28: Level types (Claude's call): `src/core/level/types.ts` has `Level`, `Station` {x, y} and `StartStation` (adds `speed`), matching the harness shape. `Obstacle` is re-exported from `sim`, as planned, and both `export *` in `src/core/index.ts` carry it without a clash. A `Level` passes straight into `simulate` (it extends `SimLevel`).
- 2026-10-29: `judge()` is defined in `src/core/judge.ts` and re-exported from `src/core/index.ts` (Claude's call; defining it in the index itself would make `level/validate.ts` import the index that imports it). Harness updated.
- 2026-10-29: Validator details (Claude's call, recorded in `src/core/level/CLAUDE.md`): beyond the harness rules it also requires finite numbers, non-empty strings, `start.speed ≥ 0`, obstacles with a size above 0 and a whole-number `par`. A station "overlaps" an obstacle when the obstacle is within `CART_RADIUS` of it. Errors come in three passes (shape, then layout and par, then the reference ride), so a broken layout never reaches the sim. Errors name the path, like `unknown field "start.sped"` or `obstacles[0].kind must be "rect" or "circle"`, and a failing reference reads `reference "5-x" doesn't win: MISSED_END at x = 10`.
